# Tether 0.10.1

Released 2026-11-02

## Highlights

- Updates no longer ask for your Mac's password to use saved passwords each time, build much faster, and no longer fail with "unable to spawn process 'metal'".

## Improved

- Updates build faster: the build folder is kept between updates (in ~/Library/Caches, which macOS may clear), so only what changed is compiled again and the packages Tether uses are not downloaded again. A build folder that no longer builds is built once more from scratch by itself.
- Builds are signed with a local certificate made once on your Mac ("Tether Local Signing" in your login keychain), so macOS recognises each update as the same app: the keychain no longer asks for your Mac's password after every update, and folder permissions stay granted.
- `make install` says that Tether may still be running in the menu bar when it refuses to replace it, and how to install what was just built without building again.

## Fixed

- Building no longer fails with "unable to spawn process 'metal'" when the Swift toolchain uses its newer build system: Tether asks for the build system that needs no Metal compiler (the terminal's shaders are compiled when Tether runs).

## Notes

- The first build signed with the local certificate (the update to 0.10.1, unless you ran `make signing-identity` before) is a new app to macOS once more: it asks for the Mac's password to let Tether use its saved passwords — choose *Always Allow* — and folder permissions are asked for again. Later updates no longer ask.
- The faster builds start with the update after 0.10.1 (the version you update from runs the update).
