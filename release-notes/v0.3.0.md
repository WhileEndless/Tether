# Tether 0.3.0

Released 2026-10-24

## Highlights

- Security: an optional App Lock (Touch ID / Mac password, or a separate Tether password) and encrypted recordings (AES-256-GCM, including compressed ones, with search and scrolling back working as before).
- Saved passwords are much harder to misuse: a server can no longer obtain the saved password of another host, and a password is never typed into a shell.
- Kubernetes in the host panel: pods and nodes of the cluster the host's kubectl reaches, with logs, describe and deleting a pod.
- Dragging tabs between windows is dependable: a detached tab can be typed in right away, no stray files appear on the desktop, and a window left empty closes by itself.
- Closing a window while another is open asks whether to keep its tabs running in the background or move them to the other window.
- Nothing printed while you are not connected is lost: the server keeps up to 100,000 lines for Tether's tmux sessions, and on reconnect the missed output is added to the terminal and its recording exactly as if it had streamed in live.

## New

- Settings ▸ Security: App Lock (off, Touch ID or Mac password, or a Tether password, optionally also unlocked with Touch ID), lock when the Mac sleeps or its screen locks, Lock Now (⌃⌘L), encrypted recordings, and Secure Keyboard Entry at password prompts.
- App Lock covers every Tether window until it is unlocked; sessions are restored only after unlocking, open sessions keep running while locked, and no terminal, shortcut or menu command works behind the lock screen. A wrong Tether password slows the next attempt down; resetting a forgotten one needs Touch ID or the Mac password.
- Encrypted recordings (AES-256-GCM, hardware accelerated), off by default and a simple on/off switch. Turning it on asks you to set a Tether password (if there is none) and encrypts all recordings, existing and compressed ones included, in the background; turning it off asks for the password and decrypts them again. Recordings still open at that moment follow when their session ends. Search, transcripts and scrolling back read encrypted recordings as usual. With "Also unlock with Touch ID" a copy of the key is kept in the login keychain so Touch ID can open Tether too. Only files on this Mac are encrypted; servers are not affected.
- Kubernetes tab in the host panel: pods (status, ready containers, restarts, node, age) and nodes of the cluster that kubectl, k3s, microk8s or oc on the host can reach, filtered by namespace or name, with logs, describe and Delete Pod. Nothing is installed on the server.
- The sidebar marks sessions and file managers that are open in another window ("Window 2"); clicking one brings that window forward, and the right-click menu can move it here. While several windows are open, each window's subtitle shows its number.
- Closing a window with tabs while another Tether window is open asks first: Keep in Background (the default — the sessions stay connected and listed in the sidebar) or Move Tabs to Other Window. The last window still just closes and comes back from the menu bar. Turned off together with "Ask before closing an online session".

## Improved

- Passwords for sudo, su and doas are kept per user: sudo's for the user who runs it and su's for the account it switches to, read from the process that asks (also on macOS, where both prompts just say "Password:"). Automatic filling works for macOS's sudo too.
- Saved passwords can be replaced (typed twice) or removed in Settings ▸ Passwords.
- Turning on encryption with a Tether password already set asks for it first; setting a new one asks for it twice.
- Forgot the Tether password: Reset (on the lock screen or in Settings ▸ Security) asks you to type RESET and for Touch ID or the Mac password, then removes the password, App Lock and encryption and the recordings nobody can open any more. Sessions, hosts, saved SSH passwords, settings and plain recordings are kept.
- Coming back to a locked Tether (unlocking the Mac's screen, clicking a Tether window, the Dock or ⌘Tab) asks for Touch ID right away; clicking anywhere on the lock screen asks too. No Touch ID prompt appears while the screen is locked or asleep, and a reconnect that needs a saved password waits until Tether is unlocked. With App Lock on, a lock button sits in the toolbar.
- When a saved password stops working (it was changed on the server, for sudo, or a key's passphrase was changed), Tether says so and the prompt offers to replace the saved password with the new one, already ticked. A rejected password is never sent again: the terminal's password bar and ⌥⌘P then ask for the new one instead.
- The password-protected key of encrypted recordings also has a backup next to the recordings (useless without the Tether password), so they stay readable even if the login keychain is reset, for example after a forgotten Mac password.
- A terminal closed without running anything keeps no recording; the archive only notes that it was opened.
- Security settings (App Lock, encryption, the Touch ID check for saved passwords, automatic filling, the ssh program and the SSH config file) are also kept in the keychain. If another program changes them in Tether's preferences, Tether puts them back at launch and says so.
- Saved passwords are typed into a terminal only when the program asking (sudo, su, ssh, …) is really in the foreground, checked with tmux right before typing; never into a shell, where the password would end up in the shell history and the recording. Automatic filling needs this check, so it works in tmux sessions only.
- Secure Keyboard Entry is on while a terminal waits for a password, so no other app can read the keys.
- The Touch ID check for a saved password now comes before the password is read from the keychain.
- Reconnecting to a tmux session adds everything the server printed in the meantime (logs, build output, ...) to the terminal's history and to the recording, in order and without repeats, instead of only redrawing the current screen. If the last thing seen is no longer on the server, everything it still has is added under a clear marker.
- New tmux sessions started by Tether keep 100,000 lines of history on the server (tmux's default is 2,000), adjustable in Settings ▸ Sessions (History kept on the server). Only Tether's own sessions get this; your tmux configuration and other sessions are not changed. New GNU screen sessions use the same limit.
- Dragging tabs no longer goes through the system's drag and drop: tabs follow the mouse directly, a small picture of the tab follows the pointer outside the tab bar, another window's tab bar lights up when the tab can be dropped there, and the result is applied the moment the mouse is released.
- Merging a window's last tab into another window (by dragging it onto that window's tab bar) closes the empty window. Dragging a window's only tab out simply moves the window.
- The window a tab is dragged to comes to the front with the keyboard in its terminal.

## Fixed

- Ctrl+L (or `clear`) in a tmux or screen session erased what was on the screen instead of moving it into the scrollback, so it was lost and ⌘↑ / ⇧⌘↑ could not reach the commands before it. Shells there clear with "home, erase below", which is now kept like any other clear.
- An ssh or scp program that no longer exists, cannot be run or sits in a temporary folder is never used; Tether falls back to /usr/bin/ssh and /usr/bin/scp.
- An independent security review of the keychain, askpass, encryption and lock code (and a second review of the fixes) found the issues below; all are fixed.
- Each askpass token now works only for the ssh process it was given to (and what that ssh starts), so a program that reads a token from another process cannot use it — not even one started from a Tether terminal.
- "Host key changed" is read only from ssh's own log, never from text a server prints.
- Open sheets show the lock screen too (Tether can be unlocked from them), so nothing behind the lock screen receives typing.
- Resetting a forgotten Tether password also turns encryption off, so recording continues; a full disk no longer leaves an encrypted recording unreadable after the failed write.
- Encrypted recordings use separate keys, derived with HKDF, for their frames and their signed header.
- A server could ask, in a keyboard-interactive prompt that imitated ssh's "Enter passphrase for key …", for the saved passphrase of a local SSH key. Passphrase and host-key questions are now recognised only when ssh itself asks them, for a key file that exists on this Mac; server-written questions are labelled as such.
- GNU screen sessions read a settings file with a fixed name in the server's shared /tmp, which another account there could have planted. The file is now private, randomly named and removed after use.
- Changes that weaken protection (no Touch ID for saved passwords, a longer grace period, automatic filling, accepting new host keys, another ssh or scp program or SSH config file, turning off Secure Keyboard Entry or locking on sleep) now need Touch ID or the Mac password; turning encryption off needs the Tether password. Restore Defaults asks first and keeps the security settings.
- Keychain items are always created fresh (readable without a prompt only by Tether), so an item another program created beforehand can never receive a secret; a recording key Tether did not create is never used.
- The app is signed with the hardened runtime, so no library can be injected into it through environment variables.
- Terminals on this Mac no longer receive Tether's askpass token, so programs run there cannot ask Tether for saved secrets.
- A server could print an imitation of ssh's "host key changed" warning and get another host's trusted key removed; Remove Old Key is now offered only for a host on the connection's own path and a file in ~/.ssh.
- Saved passwords are filled automatically only for sudo; su and other prompts need a click, the program asking is checked again after Touch ID, and passwords saved for one program's "Password:" prompt are not offered to another's.
- File and folder names from a server could break the quoting of remote commands when the login shell is fish; quoting now works the same in fish and POSIX shells.
- A new key's passphrase no longer appears in ssh-keygen's command line; ssh-add now really stores it in the keychain.
- Servers can set the Mac clipboard (OSC 52) only from the terminal being worked in, not from background tabs, other windows or while Tether is inactive or locked.
- Encrypted recordings bind every frame to its file and position, and their header is signed, so frames cannot be reordered or moved between recordings and a plain recording cannot pass for an encrypted one.
- Interrupted compression or encryption no longer leaves temporary files (possibly plain text) behind.
- Saved passwords for several users of the same server are kept apart.
- Quick Connect's "Save as host" no longer stores the password unless "Remember" is ticked; passwords kept only for the session are forgotten on lock.
- The update check opens only GitHub release pages; values typed into the host editor can no longer add extra lines to the SSH config; search export never replaces existing files.
- While locked, open sheets and password prompts are hidden too, and no window keeps a terminal focused.
- A server's keyboard-interactive prompt could name another host ("root@other-host's password:") and receive that host's saved password; a jump host could receive the target's password. Saved passwords now answer only prompts for hosts on the connection's own path, named by ssh itself.
- The askpass helper only answers processes Tether started, so another program that read a token from a process environment cannot ask for a saved password.
- Sockets for shared connections and askpass are only kept in /tmp/tether-<uid> when that folder belongs to you and is private; otherwise a private folder is used, so another account on the Mac cannot take them over.
- TETHER_* environment variables (test and demo settings) are ignored by release builds, so nothing set from outside can point Tether at other settings, ssh config or data folders.
- Saving a password replaces the keychain item in place, so a failed save never loses the old password.
- Dropping a dragged tab on the desktop or in a Finder folder no longer creates a text file there; it opens the tab in a new window as intended.
- A dropped tab no longer seemed to hesitate before moving to its new window.
- After dragging a tab out into its own window (or into another window), its terminal sometimes showed no cursor and ignored typing, because the old window took the terminal back during its fade-out. The terminal now stays with the window its tab is in, and gets the keyboard there.

## Notes

- Passwords saved for "Password:" prompts (su and similar) are now kept per program and user; one saved in an earlier version is offered again after saving it once more.
- App Lock protects Tether itself: connections that are open keep working while it is locked, and other programs running as you could use them, as with any ssh connection sharing.
- The longer server history applies to tmux and screen sessions Tether creates from now on; sessions that already exist keep their current limit.
- For tmux sessions, a lost connection is shown in the banner above the terminal rather than as a line inside it, so the screen stays exactly as the server left it.
