# Tether 0.4.0

Released 2026-10-25

## Highlights

- See what runs in a terminal: its PID, how long it has been running, CPU, memory, disk and network use, its processes and connections, below the terminal and in the new Command tab of the host panel (⌥⌘U).
- A command history on this Mac (on by default, Settings ▸ Monitoring): every command run in Tether's terminals, with its duration and the lowest, average and peak use. A command that keeps running on the server while the connection is down is followed again after reconnecting.
- Private tabs (⌥⇧⌘T): nothing is kept on this Mac, with no recording, archive entry or command history.

## New

- The bar below each terminal shows the running command: name, running time, PID, CPU, RAM and network, each labelled and explained on hover. Click it for the details. Turn it off in Settings ▸ Monitoring.
- The Command tab of the host panel shows the running command with its full command line, user, state and running time. It also shows live CPU, memory, network and disk graphs with average and peak, the process tree with CPU and memory of each process, and the command's network connections with the speed of each. There are Interrupt, Terminate and Kill buttons, and its GPU memory on hosts with NVIDIA GPUs.
- Click a connection to see where it goes: the remote address and service, the host name as the server resolves it, its speed and the bytes it moved. You can copy the address.
- Command history (Command tab ▸ History): this tab, this host or all hosts, with search. Each command shows when it started, how long it ran and its CPU, memory, thread, process, network and disk use (lowest, average, peak), plus a small graph. A command that ended while the terminal was disconnected says so, with the time span. Secrets in command lines (passwords, tokens, credentials in URLs) are masked. The history is kept for 90 days by default (Settings ▸ Monitoring) and is encrypted when recordings are.
- The history also keeps the processes each command ran (name, PID, running time, average and peak CPU, peak memory) and the connections it had (remote address and service, bytes moved, peak speed), up to 50 of each per command. Each can be turned off in Settings ▸ Monitoring.
- Export the command history as CSV (one row per command, for spreadsheets) or JSON (everything, including graphs, processes and connections), from the History list (the commands shown, or a single one) or from Settings ▸ Monitoring (all of it). Connections and traffic by process export as CSV from their context menus; the problems list can be saved as text.
- Traffic by process in the Network tab: what moves data on the whole server right now, and each process's connections with their speed. The list stays steady: it is ordered by what each process moved since you opened it (or by speed now, or by name), quiet processes fade out after a minute, and it can be filtered and paused. When a tool would help, the card suggests the install command for the server's distribution (Tether installs nothing itself). It uses nettop on macOS and the kernel's TCP counters on Linux (no root, nothing installed, nothing captured), or nethogs when it may run as root or with passwordless sudo.
- Private tabs: File ▸ New Private Tab, or "Connect in Private Tab" on a host. New tabs opened from a private tab are private too (also "New Session" after it ended). Private tabs are not reopened after quitting, and their notifications do not show what the program said. Private tabs are marked with an eye in the tab and the bar below the terminal.
- Commands are noticed the moment they start or end: one small watcher per host covers all its terminals (it reads only the shells' state, writes nothing, ends by itself). Idle terminals cost nothing, and commands that end before they could be measured are still kept with their command line and duration. Settings ▸ Monitoring can turn it off and set how often it checks and how often running commands are measured.
- All terminals of a host share one measurement: ten tabs on a server cost one look, not ten.
- ping and similar programs: their ICMP socket and target show among the connections (on Windows the target is read from the command line, as Windows shows no socket for it).
- Terminate and Kill in the Command tab end the whole command, including programs it started, so nothing keeps running in the background; the panel says when something could not be stopped.
- Settings ▸ Monitoring ▸ What Runs on Hosts lists every script Tether runs on a host, with when, what it reads and changes, how it ends, and the script itself. The same is documented in docs/remote-commands.md.
- Traffic by process now works on Windows too (connections per process, without speeds).
- Problems Tether met while looking at a host (a failed look, a missing tool, a file it could not save) are collected quietly. They appear as a small warning sign in the panel, with details you can copy. They are never printed into the terminal.

## Improved

- The command history takes little space: files are compressed, and a size limit (50 MB by default, Settings ▸ Monitoring, which also shows the space in use) removes the oldest commands first.
- Every value in the host status bar has a label (CPU, RAM, Disk, Load, Net, Ping) even in narrow windows, and a tooltip that explains it.
- The bar below the terminal shows an icon instead of the word "Recording" while output is recorded.
- Works on Linux distributions alike (Debian, Ubuntu, RHEL/CentOS, Rocky, Arch, Alpine with busybox): process data is read from /proc with awk, not from distribution-specific tools.

## Fixed

- Clicking a host in the sidebar no longer opens the host panel after you closed it. It opens again from View ▸ Show or Hide Host Panel, the toolbar, or a click in the status bar.

## Notes

- Commands shorter than the watcher's check interval (0.5 s by default) are not seen; Tether adds nothing to the shell or the server to catch them.
- Network speed per connection needs Linux 4.1 or later (TCP only). Windows lists connections, but without speeds. ICMP (ping) is not counted in bytes on any system.
