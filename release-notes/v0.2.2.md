# Tether 0.2.2

Released 2026-10-23

## Highlights

- **Fixed a crash at launch and while resizing** when the window was narrower than about 1,250 points (for example after moving it to a smaller display). The host panel is now part of the main area instead of a separate split-view column, so no window size can make the layout unsolvable; when the window is too narrow, the panel steps aside and comes back when there is room.
- **Windows come back as you left them** after quitting or a crash: every window with its tabs, selected tab, size, position and full-screen state. Windows you close yourself stay closed.
- **Many tabs to one host just work.** Logins to a host are queued (one at a time; the rest follow over the shared connection), and terminals are spread over several shared connections, because servers allow only 10 sessions per connection by default. Before, the 11th and later tabs could fail or look dead.
- **Scroll back through everything.** When you scroll past the lines kept in memory, earlier output is read back from the session's recording and scrolling just continues — the line you are looking at and your selection stay put. Back at the bottom, memory shrinks again.
- **Tether lives in the menu bar.** Closing the window keeps every session running; the menu bar icon reopens Tether with its tabs, lists sessions and starts new connections.
- **Passwords without the mouse.** A saved sudo/su password is filled the moment the prompt appears — Touch ID is the only step (none within the grace period). ⌥⌘P fills or opens a secure field.

## New

- A tab dragged out of the tab bar opens its window where it is dropped (and "Move Tab to New Window" opens it next to the current one), at the same size.
- Tether sessions left on a server — after a crash, or from tabs that never connected — are summed up under the host as "N leftover sessions" with a Clean Up button, instead of a "Detached session" row each. Your own tmux sessions are listed as before.
- Closing a session in which nothing was done (no command run, nothing running, not re-attached) needs no confirmation and leaves no empty tmux session behind on the server.
- Middle-click a tab to close it. The mouse wheel scrolls the tab bar sideways, and the ⌄ button next to it lists every tab.
- The host panel button makes room for the panel (by hiding the sidebar) when the window is too narrow to show it.
- Menu bar item (Settings ▸ General, on by default): open Tether, jump to any session, new connection, settings, quit. With no window open, Tether leaves the Dock and keeps running.
- Automatic filling of saved passwords into terminal prompts (Settings ▸ Passwords). Another host's login prompt (`user@host's password:`) is never filled on its own, and a password is not retried after it was rejected.
- Hosts with many sessions: active sessions are listed first, ended ones disappear (they are in the archive), and long lists show the first few with "Show N more". The count badge next to a host folds its sessions away.
- `scripts/long-output-test.py` prints long, numbered output to try all of this.

## Improved

- No disk writes on the main thread for everyday changes: tab switches, open sessions, the archive and host settings are saved shortly afterwards in the background (and everything pending is written at quit).
- The app stays responsive while many sessions connect: monitoring, file listings and other background work wait for a login in progress and then use its connection instead of starting logins of their own, and the "connecting" indicator no longer animates in every tab and sidebar row.
- **Lower CPU use.** Host monitoring pauses while no Tether window can be seen (covered, minimized, another Space, or closed to the menu bar). The status bar no longer measures three layouts on every update, status dots no longer use shadows (software blur on every redraw) or blink while waiting, and only the visible plain-shell session measures its latency.
- **Fewer disk writes.** Recordings are written in 512 KB / 15 s batches instead of every second, so busy output does not wear the SSD; search and scrolling write out pending output before they read. A running session's recording is never removed by the storage limit.
- Port-forward keep-alive works on Windows hosts.

## Fixed

- Closing a tab that never connected no longer leaves an empty tmux session behind on the server.
- **Disk usage on macOS hosts** showed the read-only system volume (a few percent) instead of the real usage. It now matches Finder. On Linux the percentage matches `df` (blocks reserved for root no longer count as free).
- The sidebar's list of sessions on the server is updated as soon as a session is closed or ends; a stale entry no longer leads to a dead tab, and attaching to a session that had already ended closes the attempt instead of offering a new session.
- **Closing a session that is not connected now really closes it.** A session that was still connecting, or could not reconnect, asked whether to keep it in the background; keeping it left it in the sidebar retrying ("Could not connect") forever. Such sessions now close right away. If it had a tmux/screen session on the server, that keeps running there and is listed under the host, ready to attach.
- **Retry after a failed connection tries the same session again** instead of opening a new one, so it re-attaches to its tmux/screen session on the server when that still exists.
- Sessions that end while in the background are removed instead of lingering.

## Notes

- For troubleshooting, `TETHER_CRASH_LOG=<file>` makes Tether write any crash (exception or signal) with its call stack to that file.
- Very long sessions: memory holds the configured number of lines (Settings ▸ Terminal, 10,000 by default); everything else is on disk in the recording and comes back as you scroll. With recording turned off, only what is in memory exists.
